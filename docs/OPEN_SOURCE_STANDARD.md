# Open Source Repository Standard

## Repository Class

- Repository: `yingzhou-bjtu/paper-agent`
- Class: Developer tooling repository
- Public scope: Overleaf/Cursor paper-writing tooling and local workspace automation.

## Standard Learned From Mature Projects

The checklist is based on the common public structure seen in
NumPy, PyTorch, vLLM, SGLang, and Rust: a clear root README, explicit license
and security policy, contribution guidance, CI, reproducible scripts, separated
docs/examples/tests, and a documented data or artifact boundary.

## README Contract

The root `README.md` must answer these questions in the first screen:

1. What problem does this repository solve?
2. What is the fastest safe way to inspect or reproduce it?
3. Which files or directories matter first?
4. What is included, and what is intentionally outside the repository?
5. How should users cite, contribute, report security issues, and verify changes?

## Directory Contract

Keep executable entry points in `bin/`, implementation modules in `scripts/`, docs in `docs/`, templates in `templates/`, and vendored skills under `skill/` with explicit license notes.

Current public layout to preserve:

```text
bin/
scripts/
docs/
templates/
skill/
assets/
COMPLIANCE.md
THIRD_PARTY_NOTICES.md
```

## Code and Notebook Contract

- Keep runnable source, scripts, notebooks, data, figures, and generated outputs in separate directories.
- Do not commit caches, virtual environments, credentials, local logs, or machine-specific configuration.
- Prefer one canonical entry point per workflow and document it in the README.
- When a notebook is the authoritative reproduction entry, name the dataset and expected output beside it.
- When a script is the authoritative entry, keep its arguments, environment, and output paths documented.

## Data and Artifact Contract

- Small curated fixtures may stay in Git when they are required for public inspection.
- Large raw data, generated results, model weights, and packet captures must be documented with provenance and storage policy.
- If a file cannot be regenerated by a public command, the README must say whether it is raw data, derived data, a figure, or a release artifact.
- New large artifacts should go to GitHub Releases, Git LFS, or an external dataset host unless there is a clear reproducibility reason to keep them in Git.

## Validation Contract

Before pushing:

```bash
git diff --check
```

Then run the repository-specific check from `README.md`. If the full check needs
data, Docker, GPU, credentials, or external services, document the smallest
public smoke check separately from the full reproduction path.

## Governance Files

Required public-facing files:

- `LICENSE`
- `README.md`
- `CONTRIBUTING.md`
- `SECURITY.md`
- `CODE_OF_CONDUCT.md`
- `CITATION.cff` for research, data, and paper-facing repositories
- `.editorconfig`
- `.github/workflows/` when an automated public check is meaningful
